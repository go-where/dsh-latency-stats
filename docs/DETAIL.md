# 模型性能统计

统计每个模型的**首 token 延迟**、**输出速度**与**缓存命中**，按每天的时间段（0–23 时）分桶，并给出单个会话内**每一步的缓存命中率曲线**。

## 打开方式

- 侧栏底部、设置按钮旁边：**模型性能**（侧栏收起时只剩图标）。
- 会话标题栏右侧的柱状图标：直接打开**当前会话**的统计，可在面板顶部切回「全部会话」。

## 面板内容

1. 概览：会话数、模型响应步数、平均首 token、平均输出速度、平均缓存命中、累计输出 tokens。
2. **按小时分布**：两张柱状图（首 token 延迟 / 输出速度），上方下拉框可只看某一个模型；悬停看该小时的值与样本步数。
3. **模型明细**：步数、首 token 平均 / P50 / P90、输出速度平均 / P50、流式生成速度、缓存命中、平均输出、累计 tokens。
4. **缓存命中率曲线**：x 轴是该会话的「第 N 次响应」，y 轴是命中率（%）；悬停读该次的命中率、**具体时间（精确到秒）**、上下文与缓存读取量。
   - 会话下拉按「一个会话一项」组织，子代理会话缩进挂在该会话下面；名称取自侧栏同源的会话摘要（`displayTitle`），因此未扫描过的会话也显示对话名而不是时间戳。重名不合并。
   - 从会话标题栏打开面板时，下拉默认选中当前会话。
5. **最近响应**：最近 24 次模型响应的时间、首 token、输出速度、缓存命中、输出 tokens。

曲线放在「最近响应」之前：它解释的正是上面几张表里的数字，放在最底部会让读者先看到结论再看到原因。

## 缓存命中率下降的归因

命中率**相对最近 5 次的中位数下降 ≥ 25 个百分点**即记为一次「大幅下降」，并按证据强弱给出可能原因：

| 判据 | 显示的原因 |
| --- | --- |
| 上一步与本步的 provider/model 不同 | 切换了模型/供应商，缓存不共享 |
| 两步之间有 `compaction/summary` 事件 | 上下文被压缩，约 N tokens 被摘要替换 |
| 两步之间有 `compaction/prune` 事件 | 工具结果被裁剪，约 N tokens 被替换 |
| 距上一次响应 ≥ 10 分钟 | 上游缓存可能过期（客户端重启、休眠同样落在这里） |
| 上下文比上一步缩小 ≥ 20% | 前缀被改写 |
| 下一次响应立刻回到基线 ±10 个百分点内（且以上都不成立） | 单次未命中后立即恢复，多为供应商侧缓存抖动 |
| 以上都不成立 | 前缀变化（系统提示、工具集或历史被改写） |

单个会话最多列出最近 12 次下降。

## 指标口径

时间边界与 DSH 内置的「统计」页签一致：

- **首 token 延迟** = 该步 `step/start` → 首个输出 token。首个输出 token 指第一段非空文本 / 推理片段，或第一个带名字的工具调用增量；从持久化的流记录（`time0` + 累积 `dt`）还原，历史会话同样可复算。
- **输出速度**（主指标）= 输出 tokens ÷（`step/start` → `assistant/message` 落地），含首 token，所有供应商可比。
- **流式生成速度**（辅助）= 输出 tokens ÷（首个 token → 落地），只统计真实分批到达（解码窗口 ≥ 100ms）的步。有的供应商/中转把整段回复一次吐出，此时首个 token 几乎等于最后一个 token，用解码窗口算会得到 800–8000 tok/s 的假数字——所以它只作为参考列，悬停可看“有效步 / 总步”。
- **缓存命中** = `cacheReadTokens ÷ (inputTokens + cacheReadTokens + cacheWriteTokens)`。三个桶互不重叠，`inputTokens` 是未命中缓存的那部分提示词；这也是内置统计页签的口径。
- 平均值按 token 加权（总 token ÷ 总耗时），P50 按步取中位数；缓存命中同时给出「按步平均」与「按 token 加权」。
- **时间分桶**使用本机本地时区。
- 分叉会话只统计它自己新产生的事件（`seq >= inheritedEventCount`），不会把父会话的响应重复计入。

## 性能与缓存

- 冷启动扫描会读取全部会话日志（默认最多 800 个会话 / 120 秒预算），并发 6 个；读取结果按会话保存在进程内。
- **已关闭的会话不会被重复读取**：持久化日志在不处于 live 状态时不会新增事件，所以再次扫描只重新读当前活跃的会话。实测百量级会话的重复扫描从数十秒降到几十毫秒，面板底部会显示「复用 N」。
- 单会话视图与缓存曲线共用同一次折叠结果，两处数字不会互相矛盾。
- 扫描结果缓存 2 分钟；「重新扫描」强制重建（并复用已关闭会话）。

## 已知限制

- 手动中断（取消）的步没有 `assistant/message`，不计入任何时间、速度与缓存统计——与内置统计页签一致。
- 没有 `usage` 记录的步只参与首 token 统计。
- 缓存曲线最多保留 2000 个点，超出时按步抽样并在图上标注。
- 统计以 Host 进程为边界；关闭 DSH 后缓存不保留，下次打开重新扫描。
- 只读取 `sessionQuery` 暴露的会话日志，不写任何会话事件，也不改动历史。
- 界面文案提供中文与英文；其它语言回落到英文。
